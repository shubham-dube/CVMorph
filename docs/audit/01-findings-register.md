## 2. Positive Patterns & Strengths to Keep

During the overhaul, the following architectural strengths **must be preserved**:

1. **Transaction-Scoped PostgreSQL RLS**:
   - The pattern of setting `app.current_org_id` via `SELECT set_config('app.current_org_id', :org_id, false)` is PgBouncer transaction-mode safe and provides true multi-tenant defense-in-depth.
2. **Canonical Candidate Profile JSON Schema**:
   - The structured schema ([`apps/api/app/schemas/candidate_profile.py`](file:///d:/Projects/Resume_Formatter/apps/api/app/schemas/candidate_profile.py)) with provenance metadata (`source_type`, `evidence`, `confidence`) is clean, extensible, and provides exact traceability back to source resumes.
3. **Deterministic `docxtpl` Document Rendering**:
   - Using Jinja2-templated Word XML manipulation separates document styling from business logic and allows non-technical designers to author resume templates in Microsoft Word.
4. **Interactive In-Studio AI Copilot**:
   - The conversational sidecar in Review Studio allowing natural language editing instructions is a major productivity feature for recruiters and should be expanded.
5. **Zero-Egress Object Storage**:
   - Cloudflare R2 integration avoids AWS S3 egress penalties when recruiters download large PDF/DOCX batches.
